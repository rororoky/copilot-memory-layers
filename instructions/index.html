Chapter 07 · Working with it

The instruction layer

This is the only layer your team can review line by line. It lives in the repository, moves through pull requests, and can be audited. It is also the layer people most often confuse with memory.

Why this layer exists

Accumulated memory is convenient precisely because nobody has to maintain it. That is also its weakness: you cannot guarantee what it says, when it is recalled, or how it is paraphrased. For anything that must be stated exactly — a security rule, a mandatory review step, a test command — you need authored text.

Prompt files run only in Local harness sessions. For a reusable workflow in another harness, use a skill.

Four ways guidance reaches a request

1 · Always on

Project instructions

Included in every request in the repository. Broad rules belong here, and only broad rules.

2 · Pattern matched

File-scoped instructions

A glob such as tests/**/*.py decides when the guidance is attached.

3 · Task relevance

Described instructions

In Local sessions a description lets the agent decide whether to read the file.

4 · Manual

Prompt files

You invoke them. Nothing loads until you type the slash command.

The cost of always-on

applyTo: "**" means “attach this to every file request”, which spends context on every turn whether or not it is relevant. Prefer narrow globs unless the rule truly applies everywhere.

Instructions are not enforcement

Guidance that is loaded can still be misread, partially followed, or skipped. The harness does not verify compliance. Deterministic behaviour comes from hooks, tests, and review gates — the parts of the system that do not depend on the model choosing to comply.

Mechanism Nature Use when
Instructions, skills Model-driven guidance The model should decide how to apply it
Custom agents Mixed: role text plus harness-enforced tool limits You need a narrower role or a tool boundary
Tools and MCP Model chooses whether to call The capability is optional per task
Hooks Deterministic, harness-triggered The step must happen every time

Verify in three stages

Most “my instructions do not work” problems are one of three failures. Diagnose the stage before editing the text.

  1. Discovery — is the file listed, with no validation errors?
  2. Inclusion — did this request actually attach it?
  3. Effectiveness — did the result follow it?

Repeat a representative task in a fresh chat and leave the rule out of your prompt. If the agent still applies it, the instruction is doing its job.

This site's own instruction files

The repository that builds this site contains a real .github/copilot-instructions.md and a file-scoped .github/instructions/docs.instructions.md. They are small, because a documentation site only needs a few durable rules — which is the point.
