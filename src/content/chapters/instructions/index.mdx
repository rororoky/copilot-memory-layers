## Why this layer exists

Accumulated memory is convenient precisely because nobody has to maintain it. That is also its weakness: you cannot guarantee what it says, when it is recalled, or how it is paraphrased. For anything that must be stated exactly — a security rule, a mandatory review step, a test command — you need authored text. <Cite id="vscode-instructions" />

## The artefacts

| File | What it is for | How it activates | Lives in |
| --- | --- | --- | --- |
| `copilot-instructions.md`<br />`AGENTS.md` | Project-wide conventions, commands, architecture rules. | Always included | Repository root or `.github/` |
| `*.instructions.md` | Targeted guidance for one language, folder, or task. | `applyTo` glob, or task relevance in Local sessions | `.github/instructions/` |
| `*.prompt.md` | One focused task, invoked as a slash command. | Manual, by you | `.github/prompts/` or user profile |
| `SKILL.md` | A multi-step workflow with scripts and templates. | On demand, via progressive disclosure | `.github/skills/<name>/` |
| `*.agent.md` | A role with its own instructions, tools, and model. | Selected as the agent for a task | `.github/agents/` or user profile |
| Hooks | Shell commands at lifecycle events, such as formatting after an edit. | Harness-triggered, not model-requested | Hook configuration |
| MCP servers | Access to external systems and data. | Tool call chosen by the model | Server configuration |

<p class="muted">
  Prompt files run only in Local harness sessions. For a reusable workflow in another harness,
  use a skill. <Cite id="vscode-prompts" />
</p>

  <div class="card">

  <p>
    <code>applyTo: "**"</code> means “attach this to every file request”, which spends context on
    every turn whether or not it is relevant. Prefer narrow globs unless the rule truly applies
    everywhere.
  </p>

## Instructions are not enforcement

Guidance that is loaded can still be misread, partially followed, or skipped. The harness does not verify compliance. Deterministic behaviour comes from hooks, tests, and review gates — the parts of the system that do not depend on the model choosing to comply. <Cite id="vscode-customization" />

| Mechanism | Nature | Use when |
| --- | --- | --- |
| Instructions, skills | Model-driven guidance | The model should decide how to apply it |
| Custom agents | Mixed: role text plus harness-enforced tool limits | You need a narrower role or a tool boundary |
| Tools and MCP | Model chooses whether to call | The capability is optional per task |
| Hooks | Deterministic, harness-triggered | The step must happen every time |

## Verify in three stages

Most “my instructions do not work” problems are one of three failures. Diagnose the stage before editing the text.

1. **Discovery** — is the file listed, with no validation errors?
2. **Inclusion** — did this request actually attach it?
3. **Effectiveness** — did the result follow it?

Repeat a representative task in a fresh chat and leave the rule out of your prompt. If the agent still applies it, the instruction is doing its job. <Cite id="vscode-overview" />

## This site's own instruction files

The repository that builds this site contains a real `.github/copilot-instructions.md` and a file-scoped `.github/instructions/mdx.instructions.md`. They are small, because a documentation site only needs a few durable rules — which is the point.
