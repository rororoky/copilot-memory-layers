## Progressive disclosure is the whole trick

Skills and task-relevant instructions are not loaded eagerly. The agent sees a name and a description, decides the workflow is relevant, and only then reads the full instructions and any bundled files. That keeps a large library of guidance from consuming the window before anyone needs it. <Cite id="vscode-customization" />

| Source | Loaded when | Typical cost |
| --- | --- | --- |
| Conversation and tool output | Always | Largest and fastest growing |
| Project instructions | Always | Fixed per turn |
| File-scoped instructions | A file matches `applyTo` | Only while relevant |
| Skills | The agent decides the workflow applies | Description first, body later |
| Repository and user memory | Recalled at session start | Subset of everything stored |

## Tokens are a budget, not a quota

Loaded memories count toward token usage and can affect the credits an interaction consumes. A long instruction file, a large skill, and a verbose memory all compete with the actual task: reading the right file, running the right command, seeing the failing test. <Cite id="gh-copilot-memory" />

<Callout variant="note" label="Practical rule">
  <p>
    Keep always-on instructions short and specific. Move specialised procedures into skills,
    and let memory carry the accumulated detail that would otherwise bloat a permanent file.
  </p>
</Callout>

## What this means in practice

- **A bigger instruction file is not a better one.** Precision beats volume at every layer.
- **Retrieval is a ranking problem.** Two memories can both be true and only one can be retrieved.
- **Eviction is silent.** When something is dropped to fit, the model simply proceeds without it.
- **Subagents isolate context.** Delegated work keeps intermediate noise out of the main window.
