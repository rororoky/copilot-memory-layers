The six layers

Everything Copilot “knows” during a request comes from one of six places. They differ in who owns them, how long they survive, and — most importantly — who else can see them.

1 Working memory One conversation One session You, in that session

3 Repository memory Across conversations One workspace or repository Local: you. Cloud: collaborators
4 User memory Across workspaces One person Only you
5 Source-controlled knowledge Versioned in Git Repository or user profile Anyone with repository access

Layers are additive, not sequential

It is tempting to read the stack as a pipeline — as if a fact starts as conversation and graduates into an instruction file. That is not what happens. All six are available at the same time, and the model sees a single assembled context.

What does change is the guarantee. Working memory is always present. Instructions are loaded by rule. Memory is retrieved by relevance, which means a memory existing is not the same as a memory being used.

Rule one

Scope follows the audience

Who is the information true for? Everyone in the repository becomes repository memory. Only you becomes user memory. The person who said it does not decide.

Rule two

Persistence is not visibility

A local repository note persists for months and is still invisible to your teammates. A cloud fact is visible to everyone with repository access the moment it is stored.

What all six layers share

  • They are lossy. Context windows are finite, so anything that enters can be trimmed, summarised, or dropped.
  • They compete for the same budget. Every token a memory occupies is a token not spent on code, tests, or conversation.
  • They can be wrong. A stale repository fact and an out-of-date instruction file fail in different ways, but both fail.
