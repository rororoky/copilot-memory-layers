Chapter 05 · How memory behaves

Memory lifecycle

Memory is not a database row that sits still. It is created, retrieved, checked against reality, reinforced or eroded, and eventually retired. Stepping through those six stations explains almost every surprising behaviour.

What is never stored

The system filters some content and instructs the model to avoid the rest. Knowing the list is useful: if you are relying on memory for something it will never hold, you need a different layer.

  • Secrets. Tokens, keys, and credentials are detected and the memory is rejected.
  • Model-control tokens. Recognised patterns are rejected as a defence against prompt injection.
  • Sensitive or confidential information shared in confidence.
  • Short-lived instructions. Task-specific direction belongs in the conversation or in an instruction file, not in memory.
Repository facts are shared

Anything stored as a repository fact is visible to collaborators. Treat it as documentation, not as private notes — and keep real rules in reviewed instruction files.

Reading the lifecycle correctly

Two misreadings are common. The first is that storage implies recall — it does not, because only a subset of memories is sent with a prompt. The second is that recall implies accuracy — it does not, because a fact is only as good as the citations it can still be checked against.

Both are reasons to keep a reviewed instruction layer alongside memory: one is curated by a model, the other is curated by your team.
